## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Spec F6.4: works on the JVM in dev mode; native and prod builds contain no Dev UI code. Needs an automated check so a misplaced class in runtime does not slip into prod.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 A test or build check asserts no runtime-dev or deployment class is in the prod artifact of the sample app
- [ ] #2 A native build of the sample app succeeds and contains no Dev UI code
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. integration-tests ProdArtifactIT (failsafe, after the prod package): no runtime-dev or deployment jar in target/quarkus-app nor in its dependency list, no class of runtime.dev / deployment packages nor dev-ui/ resources in any jar, no generated bytecode from the viewer's build steps; the runtime jar (inert records, SPI, config) is the only part present.
2. Native: container build of the sample app (Mandrel builder image through Docker) and the same checks on the native image (strings of the executable).
3. Run both in CI? native is too slow for every build: document the command.
<!-- SECTION:PLAN:END -->
